# لوحة Final وFinal-3 على تيرمكس

تشغل **Final الأصلي وFinal-3 بوقف 7%** داخل عمليتين منفصلتين بلوحة محلية واحدة. لا تشغل Final-2. يبقى منطق الاستراتيجية وإدارة الصفقات في ملفات البوت الأصلية دون تعديل بواسطة اللوحة.

## تحديث وتشغيل جلسات الهاتف الحالية

أوقف أي بوت أو لوحة قديمة أولًا بـCtrl+C وانتظر رجوع المؤشر. داخل أوبونتو:

```bash
cd /root/Final-3
git pull --ff-only
CASCADE_RUNTIME_DIR=/root/cascade-termux bash run_dashboard.sh
```

ثم افتح `http://127.0.0.1:8787` من متصفح الهاتف. السكربت يجلب مصدر Final من Git أول مرة ويثبت المكتبات. لا تعيد تشغيل `run_paper.sh` بالتوازي.

- **Final:** يستأنف `/root/cascade-termux/data/final.state.json` إذا كان موجودًا، برصيده وصفقاته ومراكزه السابقة. إذا غاب الملف ينشئ حسابًا جديدًا 100 USDT، فلا تمسح المجلد أو تغيره دون قصد.
- **Final-3:** يستأنف `/root/Final-3/paper_state_final3.json` نفسه الذي يستخدمه المشغل المنفرد. لا ينسخه إلى حساب آخر ولا يعيد الرصيد إلى 100. إذا كان بوقف 5% ولا توجد مراكز مفتوحة، يحفظ نسخة احتياطية ويرحل الإعداد إلى 7% تلقائيًا مع حفظ الرصيد والسجل. يرفض ترحيل المراكز المفتوحة من الإعداد السابق.
- **Final-2:** لا يشغل؛ تظل حالته وسجلاته محفوظة في المجلد القديم.
- يحفظ مسار التشغيل المحدد للمرة التالية؛ يكفي بعدها `cd /root/Final-3` ثم `bash run_dashboard.sh`.

المصدر الافتراضي لـFinal في `.runtime/repos/Final` داخل الريبو الجديد. لا يتم تعديل ملفات الاستراتيجية فيه. لتحديد مصدر Git موجود مسبقًا استخدم `CASCADE_FINAL_DIR=/root/cascade-git` إذا كان ذلك المجلد يحتوي Final الأصلي.

لتحديد حالة Final-3 مختلفة استخدم `CASCADE_FINAL3_STATE=/مسار/الحالة.json` في كل تشغيل. لا يستمر هذا الخيار المخصص تلقائيًا. ملفات القفل تمنع المشغل المنفرد واللوحة من الكتابة على حالة Final-3 نفسها معًا. ملفات الحالات المخصصة لأي بوت يجب ألا تشاركها عمليات أخرى.

## ما تعرضه اللوحة

رصيد وحقوق وهامش ومتاح لكل حساب، مراكز واتجاهاتها ووقفها وهدفها، سجل صفقات مكتملة بصافي الرسوم، سجل تنفيذات منفصل للدخول والتعزيز والخروج، تفاصيل الإشارة وسبب الإغلاق، تصدير CSV وJSON، حالة حداثة كل عملة، وسجل التشغيل. اختر البوتين أو بوتًا واحدًا من أعلى الصفحة. أزرار التشغيل والإيقاف تخص البوت المحدد.

الرصيد يعرض الجلسة السابقة إذا استؤنفت؛ الصفقات القديمة تبقى كما حدثت. تبويب الإعدادات يعرض الإعداد الحالي، وليس وصف إعداد كل صفقة تاريخية. `TRAIL_SL` يسمى «وقف متحرك» لأنه قد ينتهي بخسارة إذا تأخر التنفيذ أو تجاوز السعر الوقف.

Final-3 فقط لديه مراقب إعادة الاتصال عند توقف الشموع وفحص حداثة سعر التنفيذ. Final يحتفظ بآليته الأصلية؛ اللوحة تعرض حالة بياناته ولا تضيف إليه الإصلاح تلقائيًا.

## الإيقاف والتحديث

Ctrl+C في جلسة الخادم يوقف العاملين ويحفظ الحالة. زر الإيقاف يحفظ المركز لكنه يوقف مراقبة خروجه حتى الاستئناف. لا تحذف ملفات الحالة لعمل تحديث.

بعد الإيقاف يمكن تحديث المصدرين:

```bash
cd /root/Final-3
git pull --ff-only
git -C .runtime/repos/Final pull --ff-only
bash run_dashboard.sh
```

الواجهة محلية على loopback فقط، دون رابط عام أو أوامر تداول حقيقية أو مفاتيح Binance. أندرويد قد يوقف تيرمكس في الخلفية؛ إبقاء العملية تعمل مسؤولية إعدادات الهاتف. المحاكاة تستثني التمويل والتصفية والانزلاق.
