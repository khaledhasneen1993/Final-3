# Final-3 — الوقف والإغلاق الجزئي المتدرج

## البوت المعتمد

المدخل المعتمد الوحيد هو `cascade_final3_paper.py` والصنف `Final3PaperHunter`. جميع إعدادات البوت الفعلية في `config.py`، وتستخدمها الاستراتيجية واللوحة معًا. حُذفت ملفات Final-2 ومحرك V2 القديم من النسخة الحالية. رصيد البداية100 USDT، هامش الدخول10%، رافعة50×، وحد5مراكز. لا تعزيز ولا انعكاس في هذه النسخة.

| الإعداد | القيمة |
| --- | --- |
| الوقف الأولي | 2.8% من سعر التنفيذ |
| الإغلاق الأول | 40% عند خسارة سعرية1.2% |
| وقف بعد الأول | خسارة2.4% من الدخول |
| الإغلاق الثاني | 50% من المتبقي عند خسارة2% |
| وقف بعد الثاني | مسافة0.8% من السعر الحالي، مع الحفاظ على وقف أقرب |
| مستويات قفل الربح المعرفة | ربح1%→وقف+0.01%، 1.5%→0.5%، 2%→1%، 2.5%→1.5%، 3%→2%، 3.5%→2.5%، 4%→3% |

الفحص يبدأ بالوقف، ثم الجزئيات، ثم قفل الربح وفق النص المرسل. الوقف يتحرك إلى مستوى أقرب فقط. تبقى شروط الإشارات الأصلية والمتابعة المستمرة عبر WebSocket وتحديث قائمة أعلى40عملة كل600ثانية ومراقبة الخروج كل8ثوانٍ إضافةً لزمن الشبكة.

### الإصلاحات المطبقة والسلوك المتبقي

- عند ربح1% يُفعّل أول قفل بقيمة0.0001، أي وقف عند ربح سعري0.01% تقريبًا. هذا ليس تعادلًا صافيًا بعد الرسوم.
- لا تُسجّل مرحلة الإغلاق الجزئي كمكتملة ولا يُشد الوقف إذا فشل التنفيذ أو رفضت الكمية؛ يمكن إعادة المحاولة في الفحص التالي.
- الوقف بعد الجزئي الأول أصبح2.4%، مما يسمح بالوصول للجزئي الثاني عند خسارة2% بدل إغلاق الباقي عند المستوى نفسه.
- بعد الجزئي الثاني يُحسب وقف مرشح من السعر الحالي: `price × (1 − direction × 0.008)`، أي أسفل السعر للشراء وأعلاه للبيع. يبقى الوقف السابق إذا كان أقرب؛ المسافة الفعلية ليست0.8% بالضرورة.
- مثال شراء عند100 ثم جزئي أول ووقف97.6: عند الجزئي الثاني بسعر98 يكون المرشح97.216، فيبقى الوقف الأقرب97.6. لذلك لا يُغلق الباقي لمجرد بقاء السعر عند98 في الفحص التالي؛ يُغلق إذا تجاوز الوقف لاحقًا.
- يوجد استثناء للحسابات المستأنفة: أي وقف أقرب حُفظ سابقًا، بما فيه الوقف القديم الثابت بعد الجزئي الثاني، يُحفظ دون إبعاده. لا تُعاد المراحل المنفذة ولا تُعاد كتابة صفقاتها.
- قد يختلف سعر تنفيذ الجزئي عن سعر فحص الشرط؛ تُحدَّث الكمية من الحساب الفعلي بعد التنفيذ. إذا أفاد الحساب بإغلاق المركز كاملًا، يُحذف من قائمة الاستراتيجية دون محاولة قراءة كمية غير موجودة.

### التشغيل

يتطلب Python 3.11+ وGit واتصالًا ببيانات Binance العامة. على الهاتف شغّل الأوامر داخل Ubuntu في Termux.

للتثبيت لأول مرة:

```bash
cd /root
git clone https://github.com/khaledhasneen1993/Final-3.git
cd Final-3
bash run_paper.sh
```

لتحديث نسخة موجودة واستئناف حسابها، أوقف التشغيل الحالي بواسطة Ctrl+C أولًا، ثم:

```bash
cd /root/Final-3
git pull --ff-only
bash run_paper.sh
```

المشغّل يجهّز البيئة ويثبّت المتطلبات تلقائيًا. التشغيل الافتراضي يستخدم `paper_state_final3.json`: يستأنف الرصيد والصفقات المحفوظة إذا كان الملف موجودًا، ويبدأ بـ100 USDT إذا لم يكن موجودًا. إذا كنت تستخدم مسار حالة مخصصًا، مرّر **المسار نفسه** للاستئناف:

```bash
bash run_paper.sh --state sessions/final3-partial.json
```

لبداية منفصلة برصيد100 USDT، اختر مسارًا جديدًا غير موجود بدل حذف الحالة السابقة. لا تستخدم `--reset` للاستئناف؛ هذا الخيار يعيد الحساب المحدد إلى البداية.

### اختيار لوحة التشغيل

| المطلوب | التشغيل |
| --- | --- |
| Final-3 وحده | `bash run_paper.sh` من هذا المستودع |
| لوحة Final وFinal-3 | `bash run_dashboard.sh` من هذا المستودع |
| لوحة Final وFinal-3 وPhoenix | تشغيل `bash run_dashboard.sh` من [Final-phoennix](https://github.com/khaledhasneen1993/Final-phoennix) |

عنوان اللوحة المحلية هو http://127.0.0.1:8787. أوقف اللوحة السابقة قبل تشغيل أخرى على المنفذ نفسه. لا تشغّل البوت منفردًا واللوحة على ملف الحالة نفسه بالتزامن. تحديث هذا المستودع لا يغيّر عملية شغّالة بالفعل؛ أعد تشغيل المشغّل الذي تستخدمه لتحميل الكود الجديد. تفاصيل حسابات اللوحة وتصدير التقارير في [دليل اللوحة](dashboard/README-AR.md).

## نسخة الانعكاس انتقلت إلى Final-4

أصبح بوت الصفقات المعاكسة في مستودع مستقل: [Final-4](https://github.com/khaledhasneen1993/Final-4)، ومدخله `cascade_final4_paper.py`. هذا المستودع يشغّل نظام الوقف والإغلاق الجزئي المتدرج فقط، دون الاعتماد على ملفات بوت الانعكاس.

## ملفات النسخة المعتمدة

| الملف | الغرض |
| --- | --- |
| `cascade_final3_paper.py` | الاستراتيجية والمشغّل المعتمد |
| `config.py` | مصدر الإعدادات الوحيد؛ وقف2.8% والجزئيات40% و50% |
| `paper_account.py` | الحساب الورقي والإغلاقات الجزئية وحفظ الحالة |
| `paper_runtime.py` | بيانات السوق والمتابعة المستمرة ومراقبة الخروج والإيقاف |
| `continuous_scanner.py` | شموع WebSocket وشروط الدخول |
| `migrate_state.py` | تحديث بيانات التعريف المتوافقة مع نسخة احتياطية |
| `run_paper.sh` | تجهيز البيئة وتشغيل Final-3 |
| `dashboard/` و`run_dashboard.sh` | لوحة Final وFinal-3 المحلية |

اللوحة قد تحتفظ بقراءة سجلات قديمة مستوردة؛ هذا لا يشغّل استراتيجية أخرى. نسخة المعاكسة المعتمدة موجودة في ريبو Final-4 وحده.

## حفظ الحالة والتوافق

تُحفظ الكميات والوقف ورايات الإغلاق الجزئي والتنفيذات لاستئناف النسخة نفسها. Ctrl+C يحفظ المراكز ولا يغلقها؛ تتوقف المراقبة حتى الاستئناف.

لا تُحوَّل مراكز نسخة الانعكاس أو التعزيز المفتوحة إلى قواعد الإغلاق الجزئي الجديدة. التشغيل يرفض ذلك ويحافظ على الملف الأصلي. استخدم ملف حالة جديدًا للنظام الجديد، أو استخدم مستودع Final-4 لاستئناف حساب الانعكاس السابق بمسار ملفه الصريح. يمكن ترقية الحسابات الخالية من المراكز المعروفة مع نسخة احتياطية دون تغيير الرصيد أو حذف الصفقات. حسابات نسخة الوقف2.8% السابقة تُستأنف حتى مع مراكز مفتوحة؛ تحديث بيانات التعريف وقواعد الجزئيات ومرجع الوقف المعتمدة لا يعيد الرصيد أو الكميات أو الصفقات. تُؤخذ نسخة احتياطية، وتبقى أعلام المراحل السابقة والوقف المحفوظ كما هما؛ لا يُبعد وقف أقرب كان موجودًا قبل التحديث. لذلك قد يظل وقف قديم عند2% على مركز سبق تخفيفه أقرب من المستوى الجديد2.4%.

الحساب ورقي، دون مفاتيح تداول. أسعار التنفيذ تخضع لفحص الطابع الزمني ±10ثوانٍ. المحاكاة لا تحسب التصفية أو التمويل أو الانزلاق.
