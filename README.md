# Final-3 — الوقف والإغلاق الجزئي المتدرج

## البوت المعتمد

الملف `cascade_final2_paper.py` هو نقطة الاستراتيجية الحالية المستخدمة بواسطة `cascade_final3_paper.py` واللوحة. رصيد البداية100 USDT، هامش الدخول10%، رافعة50×، وحد5مراكز. لا تعزيز ولا انعكاس في هذه النسخة.

| الإعداد | القيمة |
| --- | --- |
| الوقف الأولي | 2.8% من سعر التنفيذ |
| الإغلاق الأول | 40% عند خسارة سعرية1.2% |
| وقف بعد الأول | خسارة2% من الدخول |
| الإغلاق الثاني | 50% من المتبقي عند خسارة2% |
| وقف بعد الثاني | خسارة1.3% من الدخول |
| مستويات قفل الربح المعرفة | ربح1%→وقف0%، 1.5%→0.5%، 2%→1%، 2.5%→1.5%، 3%→2%، 3.5%→2.5%، 4%→3% |

الفحص يبدأ بالوقف، ثم الجزئيات، ثم قفل الربح وفق النص المرسل. الوقف يتحرك إلى مستوى أقرب فقط. تبقى شروط الإشارات الأصلية والمتابعة المستمرة عبر WebSocket وتحديث قائمة أعلى40عملة كل600ثانية ومراقبة الخروج كل8ثوانٍ إضافةً لزمن الشبكة.

### السلوك الفعلي للنص المطلوب

- إذا حدث الإغلاق الأول ثم تراجع السعر تدريجيًا إلى2%، يُغلق الباقي بسبب `TIGHT_1` قبل الوصول إلى فرع `PARTIAL_2`، لأن فحص الوقف له الأولوية. إذا قفز السعر مباشرةً إلى أكثر من2% مع بقائه داخل الوقف الأول2.8%، يمكن تنفيذ الجزئيتين في الجولة نفسها، ثم يُغلق الباقي في الجولة التالية إذا ظل السعر متجاوزًا الوقف الجديد1.3%.
- شرط `profit_locked < lock` مع بداية القيمة بصفر لا يفعّل مستوى القفل0% عند ربح1%. تبدأ المستويات الموجبة لاحقًا عندما تتحقق شروطها. احتُفظ بالشرط المرسل كما هو.
- حلقة الإدارة تسجل `partial_1_done` أو `partial_2_done` وتشد الوقف حتى إذا أعادت دالة الإغلاق الجزئي `False` بسبب التقريب أو خطأ التنفيذ. لذلك العلم المسجل لا يثبت وقوع تعبئة؛ سجل التنفيذ والكمية المتبقية هما المرجع.
- لا يعاد فحص الوقف داخل الجولة بعد تشديده، وقد يتجاوز السعر الحالي الوقف الجديد حتى الجولة التالية. هذه ملاحظات تنفيذية مثبتة بالاختبارات، وليست إصلاحات مطبقة على المنطق المرسل.

### التشغيل

داخل Ubuntu في Termux مع Python3.11+:

```bash
cd /root/Final-3
git pull --ff-only
bash run_paper.sh --state sessions/final3-partial.json
```

تشغيل `bash run_paper.sh` يستخدم `paper_state_final3.json`. يمكن تشغيل اللوحة المعتادة بواسطة `bash run_dashboard.sh`. اللوحة الثلاثية في ريبو Final-phoennix تستخدم هذه النسخة الحالية عند اختيار Final-3.

## نسخة الانعكاس انتقلت إلى Final-4

أصبح بوت الصفقات المعاكسة في مستودع مستقل: [Final-4](https://github.com/khaledhasneen1993/Final-4)، ومدخله `cascade_final4_paper.py`. هذا المستودع يشغّل نظام الوقف والإغلاق الجزئي المتدرج فقط، دون الاعتماد على ملفات بوت الانعكاس.

## حفظ الحالة والتوافق

تُحفظ الكميات والوقف ورايات الإغلاق الجزئي والتنفيذات لاستئناف النسخة نفسها. Ctrl+C يحفظ المراكز ولا يغلقها؛ تتوقف المراقبة حتى الاستئناف.

لا تُحوَّل مراكز نسخة الانعكاس أو التعزيز المفتوحة إلى قواعد الإغلاق الجزئي الجديدة. التشغيل يرفض ذلك ويحافظ على الملف الأصلي. استخدم ملف حالة جديدًا للنظام الجديد، أو استخدم مستودع Final-4 لاستئناف حساب الانعكاس السابق بمسار ملفه الصريح. يمكن ترقية الحسابات الخالية من المراكز مع نسخة احتياطية دون تغيير الرصيد أو حذف الصفقات.

الحساب ورقي، دون مفاتيح تداول. أسعار التنفيذ تخضع لفحص الطابع الزمني ±10ثوانٍ. المحاكاة لا تحسب التصفية أو التمويل أو الانزلاق.
