|---|---|

| خطوة تمديد الهدف | 0.5% |

| الرسوم | 0.05% لكل تنفيذ |

مثال: رصيد 100 USDT، هامش أول 10 USDT وقيمة اسمية نحو 500 USDT. التعزيز يستهدف قيمة اسمية 500 USDT أخرى، وهامش نحو 10 USDT؛ إجمالي الهامش نحو 20 USDT للمركز قبل الرسوم والتقريب. لا يعاد حساب التعزيز من رصيد المحفظة المتغير، للحفاظ على مساواته بالدخول الأول. إذا لم يكف الهامش أو حقوق الحساب، يرفض التعزيز ويظل المركز تحت المراقبة.

بعد التعزيز، يتطابق منطق الحماية مع My-life: تضييق الوقف فورًا إلى 4% من المتوسط، وتخفيف نصف الكمية عند انعكاس 3% مرة واحدة، ثم نقل الوقف للتعادل بعد التعافي. التعادل يشمل رسوم الدخول والتعزيز والإغلاق الجزئي والإغلاق المتوقع للباقي والخسارة المحققة من الإغلاق الجزئي. التريل 1.8% / 0.9% يستمر ولا يُبعد الوقف؛ قد يبدأ قبل تعادل المركز كاملًا بعد تخفيف خاسر.

أسباب الخروج الجديدة: `TIGHT_SL` و`BE_SL` و`PARTIAL_RISK` إلى جانب `SL` و`TRAIL_SL`. الإغلاق الجزئي يحرر هامشه بنسبة الكمية المغلقة ويُحفظ لمنع تكراره بعد الاستعادة. إذا تجاوز السعر الوقف الكامل فإغلاق المتبقي له الأولوية، بما في ذلك إعادة قراءة سعر التنفيذ قبل الإغلاق الجزئي. إذا كانت الكمية لا تقبل التقسيم بعد التقريب، تبقى تحت الوقف الكامل. التنفيذ بسعر السوق المتاح لا يضمن التعبئة عند مستوى الوقف أو التعادل.

شروط الإشارة لم تتغير: حركة تتجاوز ±1.2%، حجم يتجاوز 3.5× المتوسط، عدم توازن دفتر الأوامر يتجاوز ±0.35؛ أعلى 40 عقد USDT-M مؤهلاً وتحديث القائمة كل 600 ثانية. الوقف له الأولوية على التعزيز عند القفز فوق المستويين. مراقبة الخروج كل 8 ثوانٍ كما كانت.

## إصلاح تأخر البيانات

- مراقب مستقل يفحص كل ثانيتين وصول تحديثات شموع مقبولة **لكل عملة** مشترَك بها، وليس مجرد بقاء WebSocket مفتوحًا. مهلة 15 ثانية تشمل العملات التي لم يصلها أول تحديث بعد الاتصال.
- عند تجاوز المهلة يُمنع الدخول، ويُغلق الاتصال ويعاد الاتصال مع تحميل تاريخ الشموع من جديد؛ التراجع بين المحاولات 1–30 ثانية. تأخر عملة لا يختفي خلف تحديث عملة أخرى.
- يبقى رفض إشارات عمرها أكثر من 10 ثوانٍ كما كان.
- طلب شموع التهيئة له مهلة 30 ثانية لكل عملة، وطلب سعر التنفيذ له مهلة 10 ثوانٍ.
- يُرفض سعر REST دون timestamp أو بتوقيت أبعد من ±10 ثوانٍ. هذا يشمل الدخول والتعزيز والخروج الافتراضي. عند الرفض لا تُسجل تعبئة ولا يتغير الرصيد؛ يحاول البوت في الدورة التالية. تُحفظ أوقات السوق ومصدر السعر مع التنفيذات الجديدة.
- سعر التفعيل وسعر التنفيذ يقرآن بطلبين منفصلين كما في المصدر؛ قد يختلفان بسبب تحرك السوق. لا يصطنع النموذج تنفيذًا عند سعر الوقف.

هذا يصلح غياب آلية التعافي من توقف التحديثات؛ لا يثبت سبب إغلاق صفقة IDOL السابقة، ولا يعيد كتابة نتائجها، ولا يضمن التقاط جميع الحركات. تعطل شبكة الهاتف أو إيقاف أندرويد للعملية يمكن أن يؤخر التنفيذ رغم ذلك.

## التشغيل من Git داخل أوبونتو في تيرمكس

```bash
cd /root
git clone https://github.com/khaledhasneen1993/Final-3.git
cd Final-3
bash run_paper.sh
```

يتطلب `git` و`python3` و`python3-venv`؛ ثبتها عند الحاجة عبر `apt install -y git python3 python3-venv`. السكربت ينشئ البيئة ويثبت المكتبات أول مرة. التشغيل من Git يجلب الملفات للهاتف؛ لا يلزم تنزيل ZIP. يتوفر أيضًا مشغل لوحة مشتركة لـFinal وFinal-3؛ راجع التعليمات أدناه.

الحالة في `paper_state_final3.json`، مستقلة عن حسابات Final وFinal-2. Ctrl+C يوقف ويحفظ، وتشغيل الأمر مجددًا يستأنف. لا تنسخ حالة البوتين القديمة لهذه الجلسة. المشغل يمنع نسختين على ملف الحالة نفسه، ولا يرسل بيانات لحساب اللوحة السحابي السابق حتى لو كان رمزها موجودًا في البيئة.

للجلسة المنفصلة:

```bash
bash run_paper.sh --state sessions/new-final3.json
```

## الاختبارات

```bash
.venv/bin/python -m unittest discover -s tests -v
```

اختبارات وهمية للوقف، الشراء والبيع، تعزيز متساوي القيمة، حجم 10%، خمسة مراكز، الرسوم والاستعادة والملاحقة. وتشمل تجمد الاتصال وهو مفتوح وإعادة الاتصال والتهيئة، تأخر بعض العملات، رفض أسعار قديمة وناقصة التوقيت، مهلة الطلب، وعدم إغلاق المركز بسعر قديم. نجحت 59 حالة لاختبارات البوت و11 حالة لاختبارات لوحته المحلية، ومنها الوقف الأضيق والإغلاق الجزئي والتعادل والترقية مع المراكز المفتوحة. ليست اختبار تداول حي على أندرويد.

الملفات `cascade_final2_paper.py` وأسماء الأصناف القديمة محفوظة للتوافق الداخلي. لتحديث جلسة Final-3 إلى الحماية الجديدة مع حفظ الرصيد والسجل، أوقف البوت أولًا. التشغيل يرقّي الإعدادات المتوافقة تلقائيًا مع نسخة احتياطية. ويمكن تنفيذ الترقية صراحةً:

```bash
git pull --ff-only
.venv/bin/python migrate_idle_state.py paper_state_final3.json --apply
bash run_paper.sh
```

الترحيل يحفظ نسخة احتياطية. حسابات Final-3 السابقة بوقف 7% متوافقة حتى مع مراكز مفتوحة؛ يُطبّق الوقف الأضيق على المعززة عند الاستعادة دون إبعاد وقف أقرب. إصدارات 5% وإعدادات Final-2 الأقدم لا تُرحّل إلا إذا كانت بلا مراكز مفتوحة. لا يعيد حساب الصفقات القديمة ولا يعيد الرصيد إلى 100. لا تستخدمه لنقل حساب Final-2 الحالي إلى Final-3.

المحاكاة لا تحسب التصفية أو التمويل أو الانزلاق أو هامش الصيانة؛ النتائج لا تمثل تنفيذ Futures حقيقيًا.
