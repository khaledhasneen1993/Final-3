# Final-3 — الوقف والإغلاق الجزئي المتدرج

## البوت المعتمد

المدخل المعتمد الوحيد هو `cascade_final3_paper.py` والصنف `Final3PaperHunter`. جميع إعدادات البوت الفعلية في `config.py`، وتستخدمها الاستراتيجية واللوحة معًا. حُذفت ملفات Final-2 ومحرك V2 القديم من النسخة الحالية. رصيد البداية100 USDT، هامش الدخول10%، رافعة50×، وحد5مراكز. لا تعزيز ولا انعكاس في هذه النسخة.

| الإعداد | القيمة |
| --- | --- |
| الوقف الأولي | 2.8% من سعر التنفيذ |
| الإغلاق الأول | 40% عند خسارة سعرية1.2% |
| وقف بعد الأول | خسارة2.4% من الدخول |
| الإغلاق الثاني | 50% من المتبقي عند خسارة2% |
| وقف بعد الثاني | خسارة1.5% من الدخول |
| مستويات قفل الربح المعرفة | ربح1%→وقف+0.01%، 1.5%→0.5%، 2%→1%، 2.5%→1.5%، 3%→2%، 3.5%→2.5%، 4%→3% |

الفحص يبدأ بالوقف، ثم الجزئيات، ثم قفل الربح وفق النص المرسل. الوقف يتحرك إلى مستوى أقرب فقط. تبقى شروط الإشارات الأصلية والمتابعة المستمرة عبر WebSocket وتحديث قائمة أعلى40عملة كل600ثانية ومراقبة الخروج كل8ثوانٍ إضافةً لزمن الشبكة.

### الإصلاحات المطبقة والسلوك المتبقي

- عند ربح1% يُفعّل أول قفل بقيمة0.0001، أي وقف عند ربح سعري0.01% تقريبًا. هذا ليس تعادلًا صافيًا بعد الرسوم.
- لا تُسجّل مرحلة الإغلاق الجزئي كمكتملة ولا يُشد الوقف إذا فشل التنفيذ أو رفضت الكمية؛ يمكن إعادة المحاولة في الفحص التالي.
- الوقف بعد الجزئي الأول أصبح2.4%، مما يسمح بالوصول للجزئي الثاني عند خسارة2% بدل إغلاق الباقي عند المستوى نفسه.
- بعد الجزئي الثاني يصبح الوقف عند خسارة1.5% من الدخول. هذا المستوى يكون قد تجاوزه السعر عادةً عندما تبلغ الخسارة2%؛ إذا ظل السعر عنده أو أبعد، يُغلق الباقي في فحص الإدارة التالي. لا يوجد فحص إضافي للوقف بعد التشديد داخل الجولة نفسها، وفق الكود المطلوب.
- قد يختلف سعر تنفيذ الجزئي عن سعر فحص الشرط؛ تُحدَّث الكمية من الحساب الفعلي بعد التنفيذ. إذا أفاد الحساب بإغلاق المركز كاملًا، يُحذف من قائمة الاستراتيجية دون محاولة قراءة كمية غير موجودة.

### التشغيل

داخل Ubuntu في Termux مع Python3.11+:

```bash
cd /root/Final-3
git pull --ff-only
bash run_paper.sh --state sessions/final3-partial.json
```

تشغيل `bash run_paper.sh` يستخدم `paper_state_final3.json`. يمكن تشغيل اللوحة المعتادة بواسطة `bash run_dashboard.sh`. اللوحة الثلاثية في ريبو Final-phoennix تستخدم هذه النسخة الحالية عند اختيار Final-3.

## نسخة الانعكاس انتقلت إلى Final-4

أصبح بوت الصفقات المعاكسة في مستودع مستقل: [Final-4](https://github.com/khaledhasneen1993/Final-4)، ومدخله `cascade_final4_paper.py`. هذا المستودع يشغّل نظام الوقف والإغلاق الجزئي المتدرج فقط، دون الاعتماد على ملفات بوت الانعكاس.

## ملفات النسخة المعتمدة

| الملف | الغرض |
| --- | --- |
| `cascade_final3_paper.py` | الاستراتيجية والمشغّل المعتمد |
| `config.py` | مصدر الإعدادات الوحيد؛ وقف2.8% والجزئيات40% و50% |
| `paper_account.py` | الحساب الورقي والإغلاقات الجزئية وحفظ الحالة |
| `paper_runtime.py` | بيانات السوق والمتابعة المستمرة ومراقبة الخروج والإيقاف |
| `continuous_scanner.py` | شموع WebSocket وشروط الدخول |
| `migrate_state.py` | تحديث بيانات التعريف المتوافقة مع نسخة احتياطية |
| `run_paper.sh` | تجهيز البيئة وتشغيل Final-3 |
| `dashboard/` و`run_dashboard.sh` | لوحة Final وFinal-3 المحلية |

اللوحة قد تحتفظ بقراءة سجلات قديمة مستوردة؛ هذا لا يشغّل استراتيجية أخرى. نسخة المعاكسة المعتمدة موجودة في ريبو Final-4 وحده.

## حفظ الحالة والتوافق

تُحفظ الكميات والوقف ورايات الإغلاق الجزئي والتنفيذات لاستئناف النسخة نفسها. Ctrl+C يحفظ المراكز ولا يغلقها؛ تتوقف المراقبة حتى الاستئناف.

لا تُحوَّل مراكز نسخة الانعكاس أو التعزيز المفتوحة إلى قواعد الإغلاق الجزئي الجديدة. التشغيل يرفض ذلك ويحافظ على الملف الأصلي. استخدم ملف حالة جديدًا للنظام الجديد، أو استخدم مستودع Final-4 لاستئناف حساب الانعكاس السابق بمسار ملفه الصريح. يمكن ترقية الحسابات الخالية من المراكز المعروفة مع نسخة احتياطية دون تغيير الرصيد أو حذف الصفقات. حسابات نسخة الوقف2.8% السابقة تُستأنف حتى مع مراكز مفتوحة؛ تحديث بيانات التعريف وقواعد الجزئيات المعتمدة لا يعيد الرصيد أو الكميات أو الصفقات. تُؤخذ نسخة احتياطية، وتبقى أعلام المراحل السابقة والوقف المحفوظ كما هما؛ لا يُبعد وقف أقرب كان موجودًا قبل التحديث. لذلك قد يظل وقف قديم عند2% على مركز سبق تخفيفه أقرب من المستوى الجديد2.4%.

الحساب ورقي، دون مفاتيح تداول. أسعار التنفيذ تخضع لفحص الطابع الزمني ±10ثوانٍ. المحاكاة لا تحسب التصفية أو التمويل أو الانزلاق.
